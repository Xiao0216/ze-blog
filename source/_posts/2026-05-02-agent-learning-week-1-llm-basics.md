这周学习 Agent，我没有一上来就看框架，也没有急着写一个“会自动干活”的 Demo。

真正的第一步，是先把 LLM 看明白一点。因为 Agent 再复杂，核心也还是围绕 LLM 组织输入、工具、记忆、流程和输出。如果不理解 LLM 的边界，后面很容易把模型当成一个稳定的业务引擎，结果就是 Prompt 越写越长，系统越来越不可控。

这一周我给自己的主线是：

```text
LLM = 在上下文条件下预测下一个 token 的模型
```

这句话看起来简单，但后面的很多工程判断都从这里来。

![LLM 从文本到回答的流程](/images/agent-learning/week1-llm-flow.png)

## 从一句话开始：LLM 到底在干什么

我们平时问模型一个问题，看到的是一整段回答。但模型并不是先在脑子里想好完整答案，然后一次性吐出来。

它更像是在不断做这件事：

```text
给定当前上下文，预测下一个 token 最可能是什么。
```

比如输入：

```text
今天北京的天气很
```

模型内部会得到一个概率分布：

```text
冷      31%
好      27%
热      18%
不错    12%
```

如果它选了“冷”，上下文就变成：

```text
今天北京的天气很冷
```

然后继续预测下一个 token。我们看到的一整段自然语言，就是这样一步一步接出来的。

这解释了一个很重要的边界：没有工具、没有联网、没有实时数据时，LLM 并不知道“现在几点”“明天上海下不下雨”。它最多只能生成一段像是回答的文本。

所以可靠的 Agent 不能只靠模型猜。遇到实时问题，应该调用时间、天气、搜索或数据库工具，再把工具结果交给模型组织成答案。

## Token：模型真正处理的不是句子

人看到的是句子，模型看到的是 token 序列。

```text
原始文本
  ↓
Token 化
  ↓
Token ID
  ↓
Embedding 向量
  ↓
Transformer 计算
```

Token 不是严格意义上的字，也不一定是词。它是模型的最小计算单位。

比如：

```text
人工智能
```

可能被切成：

```text
人工 / 智能
```

也可能在不同 tokenizer 下被切成别的形式。英文也一样，`unbelievable` 可能是一个 token，也可能被拆成几个子词。

Token ID 本身只是编号。比如：

```text
猫   → 3421
狗   → 9812
手机 → 120
```

从这些数字本身看不出“猫”和“狗”更近，也看不出“猫”和“手机”更远。所以模型还需要 Embedding。

## Embedding：把语义放进向量空间

Embedding 可以理解为 token 在语义空间里的坐标。

```text
猫   → [0.12, 0.88, -0.31, ...]
狗   → [0.10, 0.84, -0.29, ...]
手机 → [-0.67, 0.05, 0.71, ...]
```

向量之间可以计算距离或相似度。语义接近的词，向量方向往往更接近。

这也是 RAG、向量检索、长期记忆的基础。用户问一个问题时，系统可以把问题变成向量，再去知识库里找相似文档。注意这里不是把“相似向量”直接塞给模型，而是通过相似向量找到对应文本片段，再把文本片段放进上下文。

完整一点就是：

```text
用户问题
  ↓
Query Embedding
  ↓
向量库匹配相似 Document Embedding
  ↓
取回原始文档片段
  ↓
塞进 Prompt / Context
  ↓
LLM 基于上下文回答
```

所以 Embedding 解决的不是“回答问题”，而是“怎么用语义相似把问题和资料连接起来”。

![Token、Embedding 与向量检索的关系](/images/agent-learning/week1-token-embedding.png)

这张图对应的是从 token 到向量检索的过程：编号本身没有语义，向量空间才让“相似内容”可以被找回来。

## Transformer：让每个 token 根据上下文重新定义自己

Embedding 进入模型后，还只是孤立的语义坐标。真正让 token 带上上下文身份的是 Transformer，尤其是 Self-Attention。

Self-Attention 做的事可以说得很直白：

```text
对每个 token 计算：它应该关注句子里的哪些 token，以及关注多少。
```

例如：

```text
我把书放在桌子上，因为它太小了。
```

“它”到底指“书”还是“桌子”？模型需要根据上下文判断。Self-Attention 会让“它”和其他 token 建立注意力关系。

Transformer 里常见的 Q/K/V 可以这样理解：

```text
Q = Query：我在找什么？
K = Key：我有什么特征，别人怎么匹配我？
V = Value：如果别人关注我，我能提供什么信息？
```

流程大概是：

```text
Embedding
  ↓
生成 Q / K / V
  ↓
Q 和 K 计算相关性
  ↓
得到注意力权重
  ↓
按权重汇总 V
  ↓
得到新的上下文表示
```

这也解释了为什么同一个词在不同句子里会有不同表示。

```text
我吃了一个苹果。
苹果发布了新手机。
```

两个“苹果”的初始 token 可能一样，但经过上下文计算后，一个更偏水果，一个更偏公司。

## 训练和推理不是一回事

模型能力来自训练，但我们平时调用 API 大多是在推理。

训练阶段做的是：

```text
输入上下文
  ↓
预测下一个 token
  ↓
和真实 token 对比，计算 Loss
  ↓
反向传播计算梯度
  ↓
更新参数
```

推理阶段则是：

```text
输入
  ↓
模型前向计算
  ↓
输出
```

推理时参数是固定的。你在一次普通对话里纠正模型，它不会因此真的修改底层权重。

如果下次它看起来“记住了”，通常是外层系统在工作：

```text
当前上下文保留了你的纠正
记忆系统写入了偏好
用户画像记录了信息
数据库保存了历史
下一轮重新注入 Prompt
```

这对 Agent 很关键。很多所谓“学习能力”，不一定要训练模型参数，而是管理外部状态和上下文。

![训练和推理的区别](/images/agent-learning/week1-training-inference.png)

训练会更新参数，推理只是在固定参数上做前向计算。Agent 的“记住用户”更多发生在外部记忆、上下文和数据库里。

## 随机性：模型输出为什么不总一样

LLM 每一步输出的是概率分布，所以采样策略会影响最终结果。

`temperature` 控制冒险程度：

```text
低 temperature：更稳定、更保守、更一致
高 temperature：更发散、更有创意、更多样
```

`top-k` 是只从概率最高的前 k 个候选里选。

`top-p` 是从累计概率达到 p 的候选集合里选。

如果是写故事、头脑风暴，可以适当提高随机性。如果是生成 SQL、提取 JSON、决定是否调用工具，就应该尽量降低随机性，并且加代码校验。

这里我学到一个很实用的判断：

```text
参数只能降低随机性，不能替代权限控制、安全校验和业务规则。
```

## 一次 API 调用，其实是一条工程链路

一次 LLM API 调用不是“发一句话，收一句话”这么简单。

常见请求包含：

```text
model
messages
temperature
top_p
max_tokens
stream
stop
```

一个典型调用可以写成：

```python
response = client.chat.completions.create(
    model="qwen-flash",
    messages=[
        {"role": "system", "content": "你是一个英语老师。"},
        {"role": "user", "content": "请解释什么是 Agent。"},
    ],
    temperature=0.3,
    max_tokens=500,
    stream=True,
)
```

完整流程大致是：

```text
客户端组装 messages 和参数
  ↓
模型网关鉴权、限流、安全检查
  ↓
文本 tokenization
  ↓
模型推理和采样
  ↓
token 解码成文本
  ↓
流式或一次性返回
```

多轮对话也不是模型天然记住了你，而是调用方每次把历史 messages 重新传进去。

## 这一周的收获

这一周最重要的不是背公式，而是建立边界感。

我现在更愿意这样看 LLM：

```text
它是一个强大的概率生成器。
它能处理语言、模式、上下文和近似推理。
但它不天然拥有实时事实、业务状态、严格权限和长期记忆。
```

所以 Agent 工程不是“写一个更长的 Prompt”，而是在 LLM 外面补上：

```text
工具
记忆
检索
状态
规则
校验
人类确认
监控
```

这也是后面继续学 LangChain、Gradio、Prompt Engineering、工具调用和 Agent Runtime 的原因。

第一周先到这里。先把 LLM 当成预测器，再往上搭 Agent，心里会稳很多。
